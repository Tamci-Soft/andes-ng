Default size is now 32px high with 14px text (sm 24px, lg 40px with 16px text), shared by AndesInput, AndesInputPassword, AndesInputSearch and AndesInputOtp cells. AndesInput gains a soft count limit (`countMax`) with a custom `countStrategy` and an optional `countExceedFormatter` that trims over-long text, a custom `clearIcon` template and a `--andes-input-text-align` styling hook; AndesInputPassword gains a `visibilityIcon` template and `visibilityToggleTabIndex`; AndesInputSearch accepts a template as `enterButton` and a custom `searchIcon`; AndesInputOtp accepts a function or template `separator`, emits `(cellsChange)` with every cell on each edit and gains `blur()`; and the new AndesInputGroup lays inputs and buttons out as one attached row.

A focused field now shows a single indicator - its border in the focus colour plus a soft 2px ring, on mouse as well as keyboard focus - instead of an outline drawn a few pixels outside the border; the border also tints on hover, warning uses the deeper amber, disabled fields grey out their text instead of fading, the count is 12px, and AndesInput marks read-only fields with `andes-input-wrapper--readonly`.

The clear button now has one design shared with the other fields - a small muted disc with the "x" knocked out, 1em across with a 24px hit area, shown while the field is hovered or focused (always on touch screens), a Tab stop of its own named by the new `clearLabel` input (default "Clear"); AndesInput, AndesInputPassword and AndesInputSearch gain `(focused)` / `(blurred)` outputs carrying the native FocusEvent; and going over `countMax` now sets `aria-invalid="true"` on the input as well as turning the counter and border red, without blocking typing.
